🔑 Key Vocabulary & Definitions

Keyword Technical Definition Practical Real-World Example
HTTP Request An incoming payload/message sent from a client (browser) to the web server containing input parameters, headers, cookies, and uploaded files. Fetching submitted student records from a form via $request->input('name').
CSRF Token A unique, secret server-side cryptographic token generated to verify that the incoming POST/PUT request is coming from the authentic application user and not a malicious site. Including @csrf inside a Blade form, which generates <input type="hidden" name="_token" value="xyz123...">.
Old Input Flash-session mechanism in Laravel that temporarily retains submitted form values across a single HTTP redirect when validation fails. Repopulating a user's typed name using value="{{ old('name') }}" so they don't have to re-type it after an error.
Flash Data Temporary session data that lasts exclusively for the immediate next HTTP request, after which it is automatically cleared. Sending a success alert banner using return redirect()->with('success', 'Student created!');.
Validation Rule A constraint defined on form input fields to ensure incoming data conforms to specific application business logic before database insertion. Setting 'email' => 'required|email|unique:students,email' to prevent empty or duplicate emails.
Database Migration A version-controlled, programmatic blueprint written in PHP that defines, modifies, or drops database tables without running raw SQL queries. Executing php artisan migrate to automatically create the students table in MySQL.
Eloquent ORM Object-Relational Mapper in Laravel that maps database tables to PHP Model classes, allowing developers to query databases using object-oriented syntax. Writing Student::all() instead of executing SELECT * FROM students;.
Mass Assignment A feature that allows passing an array of key-value pairs directly to a model method like Student::create($array) to populate multiple columns at once. Populating model columns safely when $fillable = ['name', 'email', 'course', 'age'] is explicitly declared in the model.

1. Request Handling and Form Processing

1.1 What is an HTTP Request?

A Request in Laravel is represented by the Illuminate\Http\Request instance. It abstracts incoming client parameters from multiple data sources into a unified API:

INCOMING REQUEST DATA │ ┌───────────────────┬───────────────┴───────────────┬───────────────────┐ │ │ │ │ ▼ ▼ ▼ ▼ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ │ GET Query Data│ │ POST Form Data│ │ Route Params │ │ Uploaded Files│ │ (?course=) │ │ (Form Inputs)│ │ /{id} │ │ (file/photo) │ └───────────────┘ └───────────────┘ └───────────────┘ └───────────────┘

Code Implementation: Accessing Data Sources

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Route;

Route::post('/students/profile/{id}', function (Request $request, $id) {
    // 1. GET query data: /students/profile/5?ref=admin
    $referrer = $request->query('ref'); 

    // 2. POST form data
    $name = $request->input('name');

    // 3. Route parameter
    $studentId = $id; 

    // 4. Uploaded file
    if ($request->hasFile('photo')) {
        $photo = $request->file('photo')->store('student_photos');
    }

    return "Processing Student ID: {$studentId} | Name: {$name}";
});

1.2 Handling GET Forms

GET forms append input key-value pairs directly to the URL query string.

+-----------------------------------------------------------------------------------+ | URL: http://127.0.0.1:8000/students/search?course=BCA | | ▲ | | └────── Query String Parameter | +-----------------------------------------------------------------------------------+

Code Implementation (GET Form Handling):

Blade Template (resources/views/students/search.blade.php):

<form method="GET" action="/students/search">
    <label for="course">Search Course:</label>
    <input type="text" id="course" name="course" value="{{ request('course') }}">
    <button type="submit">Search</button>
</form>

Web Route (routes/web.php):

use Illuminate\Http\Request;

Route::get('/students/search', function (Request $request) {
    // Retrieve value from URL query string ?course=BCA
    $course = $request->query('course', 'All'); // 'All' is default
    return "Searching for students enrolled in: " . $course;
});
Security Warning: Never use GET forms for sensitive inputs like passwords, auth credentials, or credit card numbers, as data is visible in browser histories, server logs, and web bookmarks.

1.3 Handling POST Forms

POST forms pass input payload securely within the HTTP request body.

Code Implementation (POST Form Handling):

Blade Template (resources/views/students/create.blade.php):

<form method="POST" action="/students">
    @csrf <!-- Mandatory CSRF Security Token -->
    <input type="text" name="name" placeholder="Enter Name">
    <input type="email" name="email" placeholder="Enter Email">
    <button type="submit">Save Student</button>
</form>

Web Route (routes/web.php):

use Illuminate\Http\Request;

Route::post('/students', function (Request $request) {
    $name = $request->input('name');
    $email = $request->input('email');

    return "Saved Student: " . $name . " (" . $email . ")";
});

1.4 Essential Request Helper Methods

// 1. $request->input(): Get input value (supports default value)
$name = $request->input('name', 'Guest'); // Output: 'Guest' if 'name' is missing

// 2. $request->only(): Retrieve specific subset of keys
$credentials = $request->only(['email', 'password']); // Returns key-value array

// 3. $request->except(): Exclude specific keys
$userData = $request->except(['_token', 'password_confirmation']);

// 4. $request->has(): Check if field exists in request
if ($request->has('email')) {
    // Executes if key exists (even if string is empty)
}

// 5. $request->filled(): Check if field exists AND is not empty
if ($request->filled('email')) {
    // Executes only if email contains a non-empty value
}

// 6. $request->all(): Get all inputs as an associative array
$allInputs = $request->all();

2. CSRF Protection in Laravel

Cross-Site Request Forgery (CSRF) is a malicious exploit where unauthorized commands are submitted from a trusted user's browser to a vulnerable web application without their knowledge.

+-------------------+ 2. Hidden Attack Link +-------------------------+ | Malicious Site | -------------------------------------------> | User's Browser | | (attacker.com) | | (Authenticated Session) | +-------------------+ +-------------------------+ | | 3. Unwanted POST request | without @csrf token v +-------------------------+ | Target Laravel App | | (419 PAGE EXPIRED) | +-------------------------+

Protection Workflow

  1. When a user accesses a form, Laravel generates a unique token stored in their session.
  2. The @csrf Blade directive renders a hidden HTML input containing this token: 
    <input type="hidden" name="_token" value="d9Fa8KjL09mNxQzP3vR1...">
  3. When submitted, the VerifyCsrfToken middleware compares the form token against the session token.
  4. If tokens match, processing continues. If missing or invalid, Laravel aborts execution with HTTP 419 Page Expired.
Mandatory Rule: Always place @csrf inside forms targeting POST, PUT, PATCH, or DELETE routes.

3. Retrieving Old Input

When a validation check fails, Laravel redirects back to the previous page. Using the old() helper function ensures the form fields remain populated with the user's previously submitted data.

User Fails Validation ----> Laravel Redirects Back ----> old('field') repopulates HTML inputs

Complete Blade Input Repopulation Example

<form method="POST" action="/students">
    @csrf

    <!-- 1. Text Input Repopulation -->
    <label>Student Name:</label>
    <input type="text" name="name" value="{{ old('name') }}">

    <!-- 2. Email Input Repopulation -->
    <label>Email Address:</label>
    <input type="email" name="email" value="{{ old('email') }}">

    <!-- 3. Dropdown Repopulation -->
    <label>Select Course:</label>
    <select name="course">
        <option value="">-- Select --</option>
        <option value="BCA" {{ old('course') == 'BCA' ? 'selected' : '' }}>BCA</option>
        <option value="MCA" {{ old('course') == 'MCA' ? 'selected' : '' }}>MCA</option>
        <option value="BBA" {{ old('course') == 'BBA' ? 'selected' : '' }}>BBA</option>
    </select>

    <button type="submit">Submit Record</button>
</form>

Manual Controller Redirect with Old Input

return redirect()->back()->withInput();

FLASH DATA LIFECYCLE Request N (Store Data) ───> Session Flashed ───> Request N+1 (Display Banner) ───> Automatically Cleared

6.2 Form Request Classes

For larger applications, move validation rules into dedicated Request classes:

Step 1: Generate Form Request via Artisan

php artisan make:request StoreStudentRequest

Step 2: Configure Request Class (app/Http/Requests/StoreStudentRequest.php)

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class StoreStudentRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true; // Set to true to authorize execution
    }

    public function rules(): array
    {
        return [
            'name'   => 'required|string|max:100',
            'email'  => 'required|email|unique:students,email',
            'course' => 'required|in:BCA,MCA,BBA',
            'age'    => 'required|integer|min:16|max:60',
        ];
    }

    public function messages(): array
    {
        return [
            'name.required' => 'Student name is strictly required.',
            'email.unique'  => 'This email address is already in use.',
        ];
    }
}

Step 3: Type-Hint in Controller Method

use App\Http\Requests\StoreStudentRequest;
use App\Models\Student;

public function store(StoreStudentRequest $request)
{
    // Validated data is automatically extracted upon passing authorization/rules
    $validated = $request->validated();

    Student::create($validated);

    return redirect()->route('students.index')->with('success', 'Student added!');
}

9. Introduction to Migrations

A Migration serves as version control for your database, allowing developers to define, alter, and share schema structures using standard PHP code.

MIGRATION ARCHITECTURE PHP Migration File ──────> php artisan migrate ──────> MySQL Database Table (Blueprint Definition) (Physical Structure)

Creating Migration File

php artisan make:migration create_students_table

Migration File Structure (database/migrations/xxxx_xx_xx_create_students_table.php)

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    /**
     * Run the migrations (Creates Table).
     */
    public function up(): void
    {
        Schema::create('students', function (Blueprint $table) {
            $table->id();                                    // Auto-increment primary key
            $table->string('name');                          // VARCHAR(255)
            $table->string('email')->unique();               // VARCHAR(255) Unique
            $table->string('course');                        // VARCHAR(255)
            $table->unsignedInteger('age')->nullable();      // NULLABLE INT
            $table->decimal('fees', 8, 2)->default(0.00);    // DECIMAL(8,2)
            $table->boolean('is_active')->default(true);     // TINYINT(1) Default 1
            $table->timestamps();                            // created_at & updated_at
        });
    }

    /**
     * Reverse the migrations (Drops Table).
     */
    public function down(): void
    {
        Schema::dropIfExists('students');
    }
};

11. Models and Eloquent ORM

An Eloquent Model represents a database table entity as a PHP Class.

PHP Class: App\Models\Student <=================> MySQL Table: students Instance: $student <=================> Row: ID 1 ("Rahul")

Generating Model via Artisan

# Generate Model only
php artisan make:model Student

# Generate Model AND Migration simultaneously (Recommended)
php artisan make:model Student -m

Model Declaration (app/Models/Student.php)

namespace App\Models;

use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;

class Student extends Model
{
    use HasFactory;

    // Mass-assignment protection: Define array of column names that can be safely inserted
    protected $fillable = [
        'name',
        'email',
        'course',
        'age',
    ];
}

12. Fetching Data from Database (Eloquent Read Methods)

use App\Models\Student;

// 1. Get all records from table

$student = Student::findOrFail($id);

13. Eloquent Query Builder vs DB Facade

Laravel allows querying database layers through Eloquent ORM (Model-based) or Query Builder (DB Facade).

Eloquent Query Builder (Model Instance)

use App\Models\Student;

// Chaining Eloquent conditions
$students = Student::where('course', 'BCA')
                   ->where('age', '>=', 18)
                   ->orderBy('name')
                   ->get();

DB Facade Query Builder (Direct Table Instance)

use Illuminate\Support\Facades\DB;

// Querying directly via table name
$students = DB::table('students')
              ->where('course', 'BCA')
              ->orderBy('name')
              ->get();

Step 5: Implement Resource Controller Logic (app/Http/Controllers/StudentController.php)

namespace App\Http\Controllers;

use App\Models\Student;
use Illuminate\Http\Request;

class StudentController extends Controller
{
    // READ: Display Student List
    public function index()
    {
        $students = Student::latest()->paginate(10);
        return view('students.index', compact('students'));
    }

    // CREATE: Render Add Student Form
    public function create()
    {
        return view('students.create');
    }

    // CREATE: Store New Student Record
    public function store(Request $request)
    {
        $validated = $request->validate([
            'name'   => 'required|string|min:3|max:100',
            'email'  => 'required|email|unique:students,email',
            'course' => 'required|in:BCA,MCA,BBA',
            'age'    => 'required|integer|min:16|max:60',
        ], [
            'name.required'  => 'Student name is required.',
            'email.unique'   => 'This email is already registered.',
            'course.in'      => 'Please select a valid course.',
        ]);

        Student::create($validated);

        return redirect()->route('students.index')
                         ->with('success', 'Student created successfully.');
    }

    // UPDATE: Render Edit Form
    public function edit(Student $student)
    {
        return view('students.edit', compact('student'));
    }

    // UPDATE: Save Modifications
    public function update(Request $request, Student $student)
    {
        $validated = $request->validate([
            'name'   => 'required|string|min:3|max:100',
            'email'  => 'required|email|unique:students,email,' . $student->id,
            'course' => 'required|in:BCA,MCA,BBA',
            'age'    => 'required|integer|min:16|max:60',
        ]);

        $student->update($validated);

        return redirect()->route('students.index')
                         ->with('success', 'Student updated successfully.');
    }

    // DELETE: Remove Record
    public function destroy(Student $student)
    {
        $student->delete();

        return redirect()->route('students.index')
                         ->with('success', 'Student deleted successfully.');
    }
}

18. Security Best Practices

  1. CSRF Inclusion: Ensure @csrf is included in all Blade web forms executing state-changing POST, PUT, or DELETE calls.
  2. Strict Validation: Validate all incoming HTTP request fields on the backend regardless of frontend restrictions.
  3. Mass-Assignment Guard: Explicitly declare $fillable array properties on Eloquent Models to block malicious request injections.
  4. XSS Escaping: Output dynamic string content in Blade templates using standard {{ $variable }} syntax to ensure automatic HTML escaping.
  5. Credential Isolation: Never hardcode passwords or production DB credentials in source code. Keep credentials in .env files.
  6. SQL Injection Prevention: Avoid concatenated raw SQL strings. Use Eloquent or Parameter Binding in Query Builder methods.

19. Exam-Oriented Practice Questions

2-Mark Short Questions

Q1: What is CSRF in Laravel?

Answer: CSRF stands for Cross-Site Request Forgery. It is an attack where unauthorized requests are executed on behalf of an authenticated user. Laravel prevents this by validating cryptographic token values passed via @csrf in forms.

Q2: What is a Database Migration?

Answer: A migration is a version-controlled PHP script that programmatically builds, alters, or drops database tables without running manual raw SQL commands.

Q3: What is Eloquent ORM?

Answer: Eloquent is Laravel's Object-Relational Mapper that maps database tables to PHP Model classes, enabling developers to interact with database records using object-oriented syntax.

Q4: What is the purpose of @csrf directive?

Answer: The @csrf directive renders a hidden HTML form input field containing the user's active session security token, required to pass Laravel's CSRF verification middleware.

Q5: What is Flash Data?

Answer: Flash data is temporary session data stored exclusively for the immediate next HTTP request, typically used for success or error feedback messages.

Q6: What is the difference between find() and findOrFail()?

Answer: find($id) returns the matching record or null if absent. findOrFail($id) returns the matching record or throws a ModelNotFoundException which renders an automatic 404 Not Found response.

5-Mark Questions

Q1: Explain GET and POST form handling in Laravel with code examples.

Answer:

  • GET Form Handling: Used for retrieving, searching, or filtering data without modifying backend state. Data is visible in the URL query string. 
    // Web Route
Route::get('/search', function (Request $request) {
    return $request->query('q'); // Accesses ?q=value
});
  • POST Form Handling: Used for submitting, creating, or altering database records securely. Data is passed within the request body. Requires @csrf token directive. 
    // Web Route
Route::post('/store', function (Request $request) {
    return $request->input('name'); // Accesses POST form field
});

Q2: Explain Laravel Form Validation and Custom Messages.

Answer: Validation checks whether incoming request inputs meet defined structural rules before running controller logic. If validation fails, Laravel automatically redirects back with error messages and old input.

$messages = [
    'email.required' => 'Email address is mandatory.',
    'email.unique'   => 'This email is already registered.',
];

$validated = $request->validate([
    'name'  => 'required|string|max:100',
    'email' => 'required|email|unique:students,email',
], $messages);
