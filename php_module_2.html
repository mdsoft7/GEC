1. Introduction to OOP in PHP

Definition: Object-Oriented Programming (OOP) organises code around objects that bundle data (properties) with the functions that work on it (methods), instead of loose functions and variables.
ConceptMeaningReal-world analogy
ClassBlueprint / templateHouse plan
ObjectInstance of a classA house built from the plan
PropertyVariable inside a classColour, size
MethodFunction inside a classOpen door
EncapsulationHide data, expose controlled accessATM hides the bank vault

Use case: Large apps (e-commerce, school portals) use classes like User, Product, Order so code is reusable, organised and easier to maintain.

2. Classes, Objects, Properties & Methods

Definition: A class defines properties and methods. An object is created with new. Inside a class, $this refers to the current object; use -> to reach properties and methods.
<?php
class Student {
    public $name;            // property
    public $marks = 0;

    public function setMarks($m) {   // method
        $this->marks = $m;
    }
    public function result() {
        return $this->marks >= 40 ? "Pass" : "Fail";
    }
}
$s1 = new Student();         // object
$s1->name = "Asha";
$s1->setMarks(72);
echo $s1->name . " - " . $s1->result();

4. Constructors

Definition: __construct() is a special method that runs automatically when an object is created. It is used to set initial values.

Default constructor (no parameters)

<?php
class Car {
    public $brand;
    public function __construct() { $this->brand = "Unknown"; }
}
$c = new Car(); echo $c->brand;   // Unknown

Parameterized constructor

<?php
class Car {
    public function __construct(public $brand, public $year) {}  // PHP 8 promotion
}
$c = new Car("Tata", 2024); echo $c->brand;   // Tata

Constructor with default arguments

<?php
class Car {
    public function __construct(public $brand = "Generic", public $year = 2020) {}
}
$a = new Car();                // Generic 2020
$b = new Car("Honda");         // Honda 2020
$c = new Car("Kia", 2025);     // Kia 2025
Use case: A Database class connects to MySQL inside its constructor, so every object is ready to use immediately.

5. Encapsulation

Definition: Wrapping data and methods in one class and restricting direct access to the data, using private properties with public getters and setters that can validate input.
<?php
class BankAccount {
    private float $balance = 0;
    public function deposit(float $amt) {
        if ($amt > 0) $this->balance += $amt;
    }
    public function withdraw(float $amt) {
        if ($amt > 0 && $amt <= $this->balance) $this->balance -= $amt;
    }
    public function getBalance() { return $this->balance; }
}
$acc = new BankAccount();
$acc->deposit(1000); $acc->withdraw(300);
echo $acc->getBalance();   // 700
Diagram: outside code can only reach data through the public methods.

Use case: Stops invalid states such as a negative balance or an age of −5.

6. Inheritance

Definition: A child class gets the public and protected members of a parent class using extends, and can add its own. It promotes code reuse (“is-a” relationship).
<?php
class Person {
    public function __construct(protected $name) {}
    public function intro() { return "I am {$this->name}"; }
}
class Teacher extends Person {
    public function subject() { return "{$this->name} teaches PHP"; }
}
$t = new Teacher("Mr. Das");
echo $t->intro();     // inherited
echo $t->subject();   // own method
Animation: hierarchy – arrows show code flowing from parent to children.

Use case: Admin, Customer and Vendor extend a common User class that already handles login and profile.

7. Method Overriding

Definition: A child class redefines a method it inherited, using the same name and parameters, to give it new behaviour. parent::method() calls the original.
<?php
class Animal {
    public function speak() { return "Some sound"; }
}
class Dog extends Animal {
    public function speak() { return "Woof!"; }                  // overrides
}
class Puppy extends Dog {
    public function speak() { return parent::speak() . " (squeaky)"; }
}
foreach ([new Animal, new Dog, new Puppy] as $a) echo $a->speak() . "\n";
Some sound
Woof!
Woof! (squeaky)
Use case: Payment classes CardPayment and UpiPayment both override pay(), so checkout code just calls $p->pay().

8. Exception Handling

Definition: An exception is an object that represents an error. Instead of crashing, PHP lets you throw it and catch it elsewhere so the program can recover gracefully.
KeywordPurpose
tryCode that might fail
throwRaises an exception object
catchHandles the exception
finallyAlways runs (cleanup: close file/DB)
<?php
function divide($a, $b) {
    if ($b == 0) throw new Exception("Cannot divide by zero");
    return $a / $b;
}
try {
    echo divide(10, 2);          // 5
    echo divide(5, 0);           // throws
} catch (Exception $e) {
    echo "Error: " . $e->getMessage();   // Cannot divide by zero
    // also: getCode(), getLine(), getFile()
} finally {
    echo "\nDone";               // always prints
}

Custom exceptions (basic)

<?php
class InsufficientFundsException extends Exception {
    public function errorMessage() {
        return "Line {$this->getLine()}: {$this->getMessage()}";
    }
}
try {
    $balance = 100;
    if (500 > $balance) throw new InsufficientFundsException("Balance too low");
} catch (InsufficientFundsException $e) {
    echo $e->errorMessage();
} catch (Exception $e) {          // more general catch goes last
    echo "General error";
}
Use case: Wrap a database call in try/catch to show “Service busy, try again” instead of exposing passwords in an error page.

10. Basic DML: Insert, Select, Update, Delete

Definition: DML (Data Manipulation Language) commands change or read the data in tables. Setting query parameters means using placeholders (?) in a prepared statement and binding values separately, which prevents SQL injection.
OperationSQL
InsertINSERT INTO students(name,email,marks) VALUES(?,?,?)
SelectSELECT * FROM students WHERE marks > ?
UpdateUPDATE students SET marks=? WHERE id=?
DeleteDELETE FROM students WHERE id=?

Bind types: s string, i integer, d double.

<?php
include "db.php";

// INSERT
$stmt = $conn->prepare("INSERT INTO students(name,email,marks) VALUES(?,?,?)");
$name = "Asha"; $email = "asha@mail.com"; $marks = 82;
$stmt->bind_param("ssi", $name, $email, $marks);
$stmt->execute();
echo "Inserted id: " . $conn->insert_id;

// SELECT
$min = 50;
$stmt = $conn->prepare("SELECT id, name, marks FROM students WHERE marks > ?");
$stmt->bind_param("i", $min);
$stmt->execute();
$result = $stmt->get_result();
while ($row = $result->fetch_assoc()) {
    echo "{$row['id']} - {$row['name']} ({$row['marks']})<br>";
}

// UPDATE
$stmt = $conn->prepare("UPDATE students SET marks=? WHERE id=?");
$m = 90; $id = 1;
$stmt->bind_param("ii", $m, $id);
$stmt->execute();
echo $stmt->affected_rows . " row updated";

// DELETE
$stmt = $conn->prepare("DELETE FROM students WHERE id=?");
$stmt->bind_param("i", $id);
$stmt->execute();

$conn->close();

OOP + MySQL together

<?php
class Student {
    public function __construct(private mysqli $db) {}
    public function add(string $n, string $e, int $m): bool {
        $s = $this->db->prepare("INSERT INTO students(name,email,marks) VALUES(?,?,?)");
        $s->bind_param("ssi", $n, $e, $m);
        return $s->execute();
    }
    public function all(): array {
        return $this->db->query("SELECT * FROM students")->fetch_all(MYSQLI_ASSOC);
    }
}
$repo = new Student($conn);
$repo->add("Ravi", "ravi@mail.com", 67);
Use case: Admin panel: Insert = add student, Select = list page, Update = edit marks, Delete = remove record. Never put user input directly into the SQL string.

12. Validation of User Input

Definition: Checking that submitted data is present, correctly formatted and safe on the server before using it. Browser-side checks can be bypassed, so PHP must always validate.
<?php
$errors = [];
if ($_SERVER["REQUEST_METHOD"] === "POST") {
    $name  = trim($_POST["name"] ?? "");
    $email = trim($_POST["email"] ?? "");
    $age   = $_POST["age"] ?? "";

    if ($name === "")                                   $errors[] = "Name is required";
    elseif (!preg_match("/^[A-Za-z ]{2,50}$/", $name))  $errors[] = "Name: letters only";
    if (!filter_var($email, FILTER_VALIDATE_EMAIL))     $errors[] = "Invalid email";
    if (!filter_var($age, FILTER_VALIDATE_INT, ["options" => ["min_range" => 1, "max_range" => 120]]))
                                                        $errors[] = "Age must be 1-120";

    if (!$errors) {
        $name = htmlspecialchars($name);      // sanitise for display
        echo "Valid! Saving...";
    } else {
        foreach ($errors as $e) echo "<p style='color:red'>$e</p>";
    }
}
FunctionUse
trim()Remove extra spaces
empty()/isset()Check presence
filter_var()Validate email, int, URL
htmlspecialchars()Escape HTML on output
preg_match()Pattern check
Use case: Registration page rejects “abc@” as an email and shows all errors at once instead of crashing.

B6: Form submission and storage

Form submission is the browser sending field values to a server script when the user clicks submit. Flow: (1) user fills the form; (2) browser sends name=value pairs by POST to the action file; (3) PHP reads $_POST; (4) validates and sanitises; (5) connects with mysqli and runs a prepared INSERT; (6) shows a success or error message.

B7: Types of inheritance

<?php
class GrandParent { function a() { echo "A "; } }
class Father extends GrandParent { function b() { echo "B "; } }      // single: GrandParent -> Father
class Son extends Father { function c() { echo "C"; } }               // multilevel: -> Son
$s = new Son(); $s->a(); $s->b(); $s->c();     // A B C

Single = one parent, one child. Multilevel = a chain of classes. PHP has no multiple inheritance (a class extends only one class); use interfaces or traits instead.

C3: Inheritance + encapsulation (Employee, Manager)

<?php
class Employee {
  public static $company = "Tech Corp";
  private $emp_id; protected $name;
  function __construct($id, $name) { $this->emp_id = $id; $this->name = $name; }
  function Emp_Details() { echo self::$company . " | ID: $this->emp_id | Name: $this->name"; }
}
class Manager extends Employee {
  public $department;
  function __construct($id, $name, $dept) { parent::__construct($id, $name); $this->department = $dept; }
  function Emp_Details() { parent::Emp_Details(); echo " | Dept: $this->department"; }
}
(new Manager(7, "Meera", "IT"))->Emp_Details();

A private member of the parent is invisible to the child, so the child calls the parent method to show emp_id.

17. MySQL connection: procedural vs object-oriented

Definition: mysqli supports two equivalent styles. Procedural uses functions such as mysqli_connect() and passes $conn to each call. Object-oriented creates a mysqli object and calls methods with ->.
TaskProceduralObject-oriented
Connectmysqli_connect($h,$u,$p,$db)new mysqli($h,$u,$p,$db)
Run querymysqli_query($conn,$sql)$conn->query($sql)
Fetch rowmysqli_fetch_assoc($res)$res->fetch_assoc()
Error textmysqli_connect_error()$e->getMessage()
Closemysqli_close($conn)$conn->close()

Both examples use the school database and students table from section 9. From PHP 8.1 mysqli throws exceptions by default, so the code turns reporting on explicitly and catches mysqli_sql_exception. This works on every PHP 7+ version.

Procedural connection

<?php
// Procedural style: mysqli_* functions, $conn is passed to each function
mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);   // failures throw mysqli_sql_exception

$host = "localhost";
$user = "root";
$pass = "";
$db   = "school";

try {
    $conn = mysqli_connect($host, $user, $pass, $db);
    mysqli_set_charset($conn, "utf8mb4");
    echo "Connected successfully (procedural)";

    $result = mysqli_query($conn, "SELECT id, name FROM students");
    while ($row = mysqli_fetch_assoc($result)) {
        echo "<br>" . $row["id"] . " - " . htmlspecialchars($row["name"]);
    }
    mysqli_close($conn);
} catch (mysqli_sql_exception $e) {
    echo "Database error: " . $e->getMessage();
}

Object-oriented connection

<?php
// Object-oriented style: a mysqli object and -> methods
mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);

try {
    $conn = new mysqli("localhost", "root", "", "school");
    $conn->set_charset("utf8mb4");
    echo "Connected successfully (OOP)";

    $result = $conn->query("SELECT id, name FROM students");
    while ($row = $result->fetch_assoc()) {
        echo "<br>" . $row["id"] . " - " . htmlspecialchars($row["name"]);
    }
    $conn->close();
} catch (mysqli_sql_exception $e) {
    echo "Database error: " . $e->getMessage();
}

Reusable connection class

<?php
// db.php - reusable connection class (include it in any page)
class Database
{
    private mysqli $conn;

    public function __construct(string $host = "localhost", string $user = "root",
                                string $pass = "", string $name = "school")
    {
        mysqli_report(MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT);
        $this->conn = new mysqli($host, $user, $pass, $name);
        $this->conn->set_charset("utf8mb4");
    }

    public function getConnection(): mysqli
    {
        return $this->conn;
    }

    public function close(): void
    {
        $this->conn->close();
    }
}

try {
    $db   = new Database();
    $conn = $db->getConnection();
    echo "Connected successfully (Database class)";
    $db->close();
} catch (mysqli_sql_exception $e) {
    echo "Connection failed: " . $e->getMessage();
}
Use case: Write the class once in db.php and include it in every page, so the host, user and password live in one place.

Scenario-based assessment

Read each situation, write your answer, then open the model answer.

Scenario 1: Sign-up page crashes on a bad email

A college club's sign-up form stores whatever users type. A student enters abc@ and a name with digits; a later report fails.

Task: Where and how should validation happen? Which functions do you use, and where do the errors appear?

Model answer

Validate in PHP after POST: trim(), filter_var(..., FILTER_VALIDATE_EMAIL), preg_match() for the name. Collect all errors in an array and show them beside the fields; insert only when the array is empty. HTML5 checks alone can be bypassed.

Scenario 2: Login hijack attempt

A tester types ' OR '1'='1 in the search box and sees every student record.

Task: Name the attack, explain why it worked and fix the code.

Model answer

SQL injection: user input was concatenated into the query. Use a prepared statement with ? and bind_param("s",$email); also escape output with htmlspecialchars().

Scenario 3: Wallet app allows negative balance

An online wallet lets a script set $wallet->balance = -500.

Task: Redesign the class so this cannot happen. Which operations does it need and which exception can it throw?

Model answer

Make balance private; expose deposit(), withdraw(), getBalance(). In withdraw() throw InsufficientFundsException (extends Exception) when amount > balance; the caller uses try/catch/finally.

Scenario 4: Three user roles, one login

A portal has Admin, Teacher and Student users; all need login() and profile(), but each has a different dashboard().

Task: Which OOP concepts do you apply? Sketch the classes.

Model answer

Inheritance and overriding: parent User with login() and profile(); children extend it and override dashboard(). Calling $user->dashboard() gives role-specific output. Call parent::__construct() to reuse setup.

Scenario 5: Search page shows the wrong method

A search page uses POST; users cannot bookmark or share result links, but a registration page uses GET and shows the password in the URL.

Task: Correct both pages and justify.

Model answer

Search: GET ($_GET) so URLs are shareable. Registration/login: POST so passwords are not in the URL, history or logs. GET is for safe read-only requests, POST for changing data.

Scenario 6: Database is down during checkout

MySQL stops during peak sales and customers see a raw error with the DB username.

Task: How do you handle it gracefully and always release resources?

Model answer

Enable mysqli_report(MYSQLI_REPORT_ERROR|MYSQLI_REPORT_STRICT), wrap connect/query in try/catch (mysqli_sql_exception), show 'Service busy, try again', log the real message, and close the connection in finally.

Scenario 7: Survey loses checkbox answers

A survey with hobbies checkboxes only ever stores the last hobby, and unticked boxes cause an 'undefined index' warning.

Task: Find both bugs.

Model answer

Checkbox names need [] (hobbies[]) so PHP receives an array; read it with $_POST['hobbies'] ?? [] and store with implode(', ', ...). Unchecked boxes are never sent.

Scenario 8: Profile photo upload rejected

Students upload a 5 MB PDF as their profile picture and the server accepts it.

Task: List the checks the script must make and the form change needed.
